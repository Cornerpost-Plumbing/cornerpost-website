# Cornerpost Standard

**Standard ID:** UI-001  
**Standard Name:** User Interface & Form Design Standard  
**Approval Status:** Approved  
**Revision:** 1.0

# Purpose

This standard defines the long-term philosophy for the design of all Cornerpost user interfaces and forms.

It applies to public-facing websites, internal business applications, administrative tools, customer portals, mobile interfaces, desktop applications, and future digital systems.

This is not a technical implementation standard. It defines how Cornerpost software should communicate with its users.

# Scope

This standard applies to every digital interface developed for Cornerpost Plumbing.

# Design Intent

Every Cornerpost interface should reduce uncertainty.

A user should always understand:

- What information is being requested
- Why it is being requested
- What will happen next
- What action should be taken

Interfaces should feel organized, calm, and thoughtfully designed. The software should support the work rather than becoming the work.

# Standard Requirements

## 1. Clarity Before Efficiency
Reducing clicks is not the primary objective. Reducing confusion is. An additional click that prevents mistakes is preferred over a faster interface that increases uncertainty.

## 2. Group Information by Purpose
Group related information visually. Organize forms around meaningful tasks rather than database structure. Information should flow in a logical sequence whenever practical.

## 3. Visual Hierarchy
Communicate importance through typography, spacing, and layout. Primary information should stand out while secondary information supports the task without competing for attention.

## 4. Purposeful Simplicity
Every visible element shall serve a purpose. Avoid unnecessary borders, icons, animations, colors, visual effects, and decorative graphics. White space is a functional design tool.

## 5. Consistency
Buttons, form controls, spacing, typography, terminology, navigation, feedback messages, and workflow patterns shall behave consistently across all Cornerpost software.

## 6. Forms Should Feel Conversational
Collect information in the same order an experienced professional would naturally ask questions. Users should feel they are providing information to solve a problem, not completing paperwork.

## 7. Placeholder Text
Use placeholder text only when it provides guidance. Dropdowns should begin with instructional prompts rather than valid selections.

## 8. Primary Actions
Each screen or form shall have one clearly identifiable primary action. Secondary actions should never compete visually.

## 9. Accessibility
Prioritize readability, adequate contrast, clear labels, and logical navigation over visual trends.

## 10. Feedback
Communicate successful completion, errors, warnings, required corrections, and current status using informative, non-technical language that explains what happened and what to do next when appropriate.

## 11. Long-Term Maintainability
Favor reusable interface patterns over one-off solutions. Consistency reduces maintenance while improving usability.

# Implementation Guidance

Apply this standard whenever designing or modifying interfaces, forms, workflows, dialogs, or navigation. When multiple acceptable solutions exist, choose the one that reduces uncertainty and improves long-term consistency.

# Exceptions

Exceptions should be documented whenever deviation provides a measurable improvement to usability, accessibility, or operational effectiveness.

# Philosophy

Cornerpost software should reflect the same values as Cornerpost Plumbing:

- Thoughtful
- Professional
- Calm
- Organized
- Reliable

The objective is not to create software that feels impressive. The objective is to create software that people immediately understand and confidently use.

Users should spend their attention solving plumbing problems, not learning the interface.

Every design decision should reduce uncertainty, improve clarity, and strengthen confidence.
